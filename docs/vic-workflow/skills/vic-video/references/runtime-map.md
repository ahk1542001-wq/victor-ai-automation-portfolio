# Public runtime boundary

This export contains the actual shared scripting/production instructions and five style adapters, generalized for public review. It does not include the owner's renderer implementations, avatar sprites, generated artwork, voice recording, cloud driver, job history or configured accounts. Reading instructions does not grant those capabilities. Do not execute an unresolved LOCAL_RUNTIME_PATH.

Before producing media, map a selected style to an authorized, independently installed local runtime and inspect its real CLI, asset schema, fonts and supported operations. Do not assume an example command from the original owner environment works on another computer. Configure project-owned job paths rather than searching private historical job folders.

| Style | Runtime family to configure | Excluded runtime resources |
|---|---|---|
| vic-sh-uiMotion | HTML/browser capture and FFmpeg | ShortForm templates, presenter manifest and executable object/action schema |
| vic-sh-visualStory | Same short renderer plus authorized fresh cartoon generation | Artwork tooling, calibrated rigs and character-motion assets |
| vic-lg-spatialMotion | HyperFrames/GSAP | Film assets, camera/face helpers and fixture-specific builders |
| vic-lg-cartoonStory | AniDoodle-based Canvas/FFmpeg | Original host rig, camera helper and film modules |
| vic-lg-paperMotion | Canvas/JS with Python/Playwright and FFmpeg | Paper engine, film data and rendering/QA entry points |

The linked runtime guides describe requirements, not vendored software. Consult the repository setup/rights documents before installing or redistributing third-party dependencies. Preserve upstream licenses and keep the restricted KAPE mascot out of distribution.

The bundled paper_timing.py and its tests are standalone timing conversion only. They verify a shared voice assembly receipt and produce scene timing without changing waveform bytes. They cannot synthesize speech or render a movie. Run tests with `python3 -m unittest discover -s tests` from the skill directory.

The shared voice method is documented in the repository voice-and-colab guide. Its private driver/reference are deliberately not exported. Use only a locally configured authorized voice procedure and check current compute policy before generation.
