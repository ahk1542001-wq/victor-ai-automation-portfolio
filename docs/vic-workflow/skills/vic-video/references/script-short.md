# Short script pattern

Teach one useful idea or task through one coherent example. Short means focused; it is not a compulsory60-second limit, nor a reason to rush Burmese speech. Use actual measured narration for the final duration.

A useful pattern is: recognisable problem or outcome hook → who benefits/what it helps with → only the missing mental model → one input/agent/tool/result sequence → material limitation or human check → one practical next step. An output teaser can lead. Rearrange or omit a beat when the topic is clearer another way; do not create one title card per beat.

For tool/repo topics, make purpose/audience/payoff clear before implementation details. Keep creator/license/update context concise and dated; it supports the use case rather than becoming the script. Distinguish an observed demo from an illustrative workflow. Give the viewer enough preparation/input context to understand the result without a glossary lecture.

Make each spoken point earn a visible action, comparison, reaction or result. A longer explanation needs meaningful internal progression, not one popup held under a paragraph. Preserve natural breaths and readable result holds; do not accelerate voice to hit a guessed length. Narration and on-screen main points are separate text fields. End when the promised useful idea is understood, not after a mandatory greeting/CTA/filler.

Main checks the hook/payoff, factual support, beginner teach-back, pronunciation and visual feasibility before script approval. Scene count, examples, analogies, palette and sound are chosen for the new topic.
